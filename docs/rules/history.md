# 中国区历史壁纸规则

状态：CURRENT；版本：1.3.0；生效：2026-10-21；维护者：项目维护者。
代码：[history.mjs](../../lib/history.mjs)、[jpeg.mjs](../../lib/jpeg.mjs)；测试：[history.test.mjs](../../test/history.test.mjs)、[浏览器测试](../../test/browser-ui.test.mjs)。

## DP-HISTORY：年月目录与记录来源

仅支持中国区 `zh-CN`。月份范围为 2018-09 至 Asia/Shanghai 当前月；年月目录只表示可以查询的范围，不保证每一天有记录。日期必须是真实公历日期且不晚于中国当天；禁止路径、URL、未知市场及未来月份。zxyongyo 首月最早收录 2018-09-11；npanuhin 中国区始于 2024-04-03。首月可能不满月。

只读取所选月份适用来源的固定 JSON（2018-09 起 zxyongyo，2024-04 起另加 npanuhin），单月最多 31 项、每个日期一项。归档源日期按其 `date` 原值使用，不再移动时区；Bing 新记录继续按 DP-DATE 规则转换。按日期降序输出，不为缺档补图。同日优先级为 Bing 每日索引 > npanuhin > zxyongyo，优先来源提供标题和说明；仅在图片 ID 一致时沿用归档图片副本标记及此前检查结果，ID 改变则重新检查。归档刷新不会删掉本地已保存、上游暂时缺失的记录。

每项保留图片 ID、市场、日期、标题、说明、摄影版权、索引来源、来源链接、是否有归档副本和可用性状态。归档没有 Bing ID 时使用稳定的 `OHR.HistoryCN_YYYYMMDD` 本地标识；历史图片通过日期及期望图片 ID 路由请求，ID 不匹配时提示重新打开月份，不把该标识送给 Bing。收藏保留这些附加字段，原有收藏保持可读。

## DP-HISTORY-STORE：持续保存与恢复

历史元数据存放于独立 `HISTORY_DIR`，默认项目根 `.history/`；每月 `YYYY-MM.json`，格式版本 1。使用同目录临时文件和原子重命名；同进程写入串行化，合并总是在锁内重新读取，避免采集、归档和图片检查互相覆盖。损坏历史文件返回错误并保留原文件，不静默当成空目录覆盖。该目录不随图片缓存淘汰；备份与跨版本部署须单独保留。一个历史目录只供一个 Node 服务进程写入。

服务启动后立即获取中国区最近窗口，此后每轮结束一小时再采集；失败也会进入下一轮，不重叠执行。中国区成功刷新或首次读取有效近期缓存时，也把每日索引合并进对应月份。重复请求同一份近期归档复用索引写入结果，不反复写盘；元数据刷新仍可更新标题和版权。采集不下载原图。保存失败不妨碍每日精选使用，但返回 `historyWarning`，历史目录报告同步失败。`sync.json` 保存最近成功写入时间。

关闭网页后，只要 Node 服务仍运行就会采集；关闭服务或机器休眠时无法保证定时采集。重启可补最近 15 天窗口，更久缺口依赖归档源已经收录的日期。索引持续保存不等于原图永久备份，也不构成每天绝不漏采的保证。

每个来源独立保存成功/缺档时间，不把一个来源的新鲜度当作另一个来源已读取。旧 schemaVersion 1 文件的 providerFetchedAt 只恢复为 npanuhin 的时间，新增来源首次访问即读取。来源字段和 providers 为兼容性新增字段；原文件无需批量迁移。

月索引在线有效期：当前月 1 小时，历史月 24 小时；手动刷新可绕过有效期，但每月每个来源实际刷新至少间隔 60 秒。相同月份在途读取合并；单源失败仍合并另一源成功数据，保留本地索引并标记 `stale`。上游 404 是显式缺档，保留本地每日记录；网络/5xx/JSON 异常不伪装成空月。一个来源缺档、另一个失败且无保存记录时不能断定空月；没有可用索引时返回 502，资源满返回 503。

## DP-HISTORY-IMAGE：旧图检查与资源预算

有归档副本时优先读取该 JPEG；否则先请求同图 Bing UHD。前一候选失败时，依次尝试同一 ID 的 Bing UHD 和 zxyongyo 记录的尺寸变体（若有且不同）。不使用同一天的另一图片 ID 来替代失败图片。没有本地日期索引时图片接口返回 404，须先打开相应月份。来源仅为固定 `bing.npanuhin.me/CN/zh/YYYY-MM-DD.jpg`、`www.bing.com/th` 或 `cn.bing.com/th` 图片适配，不请求元数据任意 URL，不跟随重定向。

所有历史请求与近期 Bing 共用 DP-RESOURCE 的 4 槽/32 等待位置、超时、重试和正文上限；月 JSON 上限 1 MiB，图片上限 20 MiB；同图所有候选和重试共用 20 秒总时限，最多三个候选。图片检查 Content-Type、JPEG 首尾、段长度、尺寸及扫描段；宽至少 320、高至少 180，总像素不超过一亿。拒绝 HTML、明显截断和异常小图；这不是完整解码或语义比对，无法识别任意正常尺寸的错误画面。浏览器实际解码失败也显示重试提示。

可用性初始 `unchecked`，实际读取成功后记录 `available`、检查时间和像素尺寸；确定获取/结构失败记录 `unavailable`，临时网络/容量失败（包括上游 408、429、5xx）记录 `error`。失败不删除元数据，不缓存失败图片；60 秒内复用失败状态，随后可重新检查恢复。列表不预先探测整月或整库图片。可用状态只是此前一次观察，源站与缓存变化后可能不同。

历史图片缓存键包含日期、图片 ID 和归档/Bing 来源，避免同日图片更换后复用旧字节，与近期图片共用 140 项/256 MiB 淘汰预算。浏览器图片也共用原 80 项/64 MiB 预算。历史下载保存实际获取的 JPEG，主图成功解码后显示真实像素尺寸；仓库 url_4k 可能是请求参数生成的变体，分辨率达到 3840×2160 也不能证明原生 4K 细节。不提供额外裁切选项。

## DP-HISTORY-UI：按需浏览

年份/月选择只加载一个月的元数据，最多展示 31 项。切换时取消前端旧请求并检查 generation，迟到结果不覆盖新月份或其他标签。缩略图通过 IntersectionObserver 接近视野 80 像素时入队，同时最多加载两张；切换列表或离开页面时取消旧缩略请求并释放队列槽位，旧图片的迟到事件不影响新列表；缺少该 API 时回退浏览器原生 lazy。主图仅加载当前选中图片，历史模式不预热整月原图。当前历史缩略图使用同一原图接口并与主图共享缓存；高分辨率原图仍可能较慢。

网站页脚和 README 明确列出 `npanuhin/Bing-Wallpaper-Archive`（索引与图片备份）及 `zxyongyo/bing-daily-wallpaper`（索引与 Bing 链接），关于对话框、图片详情及第三方声明同步来源；保留摄影版权。年月选择区不放来源声明。空档、网络异常、加载中、单图失败分别提示；用户可选其他月份/图片或重试。离线月索引独立缓存最多 13 个请求条目（包括年月目录），不占用精选归档缓存；仅能离线读取已经保存且未淘汰的月份与图片。
