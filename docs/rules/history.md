## DP-HISTORY：年月目录与记录来源

仅支持中国区 zh-CN，范围为 2018-09 至 Asia/Shanghai 当前月；目录表示可查询范围，不保证每一天有记录。日期必须是真实公历日期且不晚于中国当天。zxyongyo 首月最早收录 2018-09-11，npanuhin 中国区始于 2024-04-03；首月可不满月，不为缺档补图。归档日期原样保留；Bing 新记录依 DP-DATE 转换，不根据 OHR 市场后缀更改源日期。

日常浏览仅读取本站 HISTORY_DIR 的月文件和图片。第三方适配只能由明确的 import 模式使用；导入工具一次性读取两来源，保留摄影版权、来源与原始 ID，独立保存到本站。按日期合并，每日一条、每月最多 31 条，降序展示；同日优先级 Bing > npanuhin > zxyongyo。ID 相同才合并贡献来源、图片备份标记与此前检查结果；ID 不同使用优先记录并重新检查，不借另一张图片填补失败。

每项保留 ID、市场、日期、标题、说明、版权、来源链接、source/sources、snapshot、availability；没有 Bing ID 的备份使用 OHR.HistoryCN_YYYYMMDD，不把该标识送给 Bing。普通 API 不请求用户提供的 URL。导入刷新不会删除本地已有、源端暂时缺失的记录。同一 Bing 采集窗口若同日有多个图片 ID，月索引及 latest.json 均取适配器按发布时间降序排列后的第一项。单个历史来源月数据出现非法地址、日期或结构时拒绝该批；本地导入工具额外隔离同日尺寸链接指向不同 ID 的记录，保留其日期/ID/原因到 import-report.json，不猜测正确链接。其余有效记录继续导入。

## DP-HISTORY-STORE：采集、持久化与恢复

HISTORY_DIR 默认项目根 .history；每月 YYYY-MM.json，schemaVersion=1。月数据和同步状态使用临时文件加原子重命名，同进程写入串行，合并前重新读取。损坏文件报错并保留，不能当成空文件覆盖。一个目录仅允许一个服务进程写入，导入必须在隔离目录；导入锁防止重复导入进程，异常退出后须确认进程结束再清理锁。重跑复用已保存的索引和图片，并生成本轮报告。

GitHub Actions 每日计划 UTC 21:17（北京时间次日 05:17），并支持手动运行；从 Bing 的 idx=0/7、n=8 两批取得最多最近十五日，完整验证后按日期合并到自己的 codex/wallpaper-data 分支。两批失败之一不更新 latest.json，也不提交数据分支；已有历史月文件保留。GITHUB_TOKEN 仅 contents:write，固定官方 action 提交，串行普通推送。调度可能延迟；不能将一次成功视为永久每日运行保证。

服务启动后立即读取自有分支 latest.json，此后每轮结束一小时重试；仓库由 HISTORY_REPOSITORY 指定，默认 oonecab/daily-picture-web。HISTORY_COLLECTOR=off 关闭本机后台采集。只接受 schemaVersion=1、zh-CN、1～15 条唯一有效日期、合法 ID 和字符串；fetchedAt 必须有效且不超过当前时间五分钟。超过 48 小时仍可补保存，但状态明确报告过期。每轮两张并行保存图片，失败保留索引并记录到 sync.json，下轮重试。游客历史请求不会触发下载或访问两个第三方项目。

近期中国区归档的成功读取仍追加元数据到本地月份，失败用 historyWarning 提示；图片由后台同步保存。sync.json 分别保留 lastSuccessAt（索引落盘）、fetchedAt（Actions 采集时间）、lastMediaSuccessAt（整轮图片保存成功）、失败明细和错误，不混淆写入时间与采集新鲜度。停机后可补最新十五日，超出窗口的遗漏无法保证找回。

月文件、原图和媒体清单独立于 .cache 淘汰，需备份整个 HISTORY_DIR 并监控磁盘；不能只备份 Git 索引。旧 schemaVersion=1 月文件兼容读取，逐来源 providers 和 importedAt 为可选字段。迁移使用新目录，停旧服务后合并最新记录并保留旧目录，回滚不删除图库。

## DP-HISTORY-IMAGE：图片可用性与资源预算

仅入库流程请求图片。历史导入依次尝试归档副本（若有）、同 ID Bing UHD、来源记录的 1920x1080 文件加 3840×2160 参数。日常后台仅用 Bing，不读第三方图片。限固定 HTTPS 主机和路径、禁止重定向，同图候选总预算 20 秒；共享上游 4 槽/32 等待位置，JSON 上限 1 MiB、图片 20 MiB。导入最多四张并行，日常同步两张。

原图须通过 HTTP JPEG 类型、完整结构、至少 320×180 和 Sharp 完整解码检查；输入最多 40 百万像素，防止解码耗尽内存。Sharp 同时最多处理两张、32 个等待位置，各派生图处理最长 15 秒。拒绝 HTML、截断、过小占位图和不可解码扫描数据；不能识别所有正常尺寸但画面错误的图片，不宣称逐图人工语义核对。

media 目录按日期和 ID 摘要命名，持久化原图原始字节、最长宽度 640 的缩略图、最长宽度 1920 的预览。保持比例、处理方向、不放大小图；缩略图 JPEG 质量 78、预览 86。清单保存三者的字节数、SHA-256 和实际尺寸。清单最后原子提交；读取时核对字节数/摘要，损坏文件不返回；仅派生图损坏时可从本站原图重建。源图片缺失时访客接口返回 404，交由后台恢复，不悄悄转发第三方。

初始 availability=unchecked；保存成功为 available、stored:true、width/height 与 checkedAt。确定失效为 unavailable，临时网络/资源错误为 error；失败不删除索引、不保存失败正文，60 秒失败冷却。HTTP 成功不代表图片有效；已检查状态只说明上次观察。下载返回原图原始字节，并显示保存时的实际尺寸；4K 链接或达到 3840×2160 不证明原生细节，不提供额外裁切。

## DP-HISTORY-UI：按需浏览与声明

只读取所选月元数据，最多 31 项；切月取消旧请求并核对 generation，迟到结果不覆盖新月。缩略图接近视野 80 像素后入队，最多两张同时加载，切换列表/离开页面释放请求和槽位；缺少 IntersectionObserver 回退原生 lazy。只加载当前主图预览，点击下载才读取原图，不预热整月。各尺寸有不同 URL 缓存键，浏览器仍共用 80 项/64 MiB 图片预算；历史元数据缓存最多 13 项。服务器原图库不参与这些淘汰。

网站“关于每日一景”、图片详情与 README 保留两项目名称、链接和初次导入贡献，摄影版权继续展示。首页页脚提供同步状态、Bing、项目源码和“关于”入口。空档、加载、失败分别提示，重试只重读本站数据。离线可用范围取决于浏览器已保存且未淘汰的资源。
