## 大图与慢客户端对照

采用相同 6,834,467 字节、3840×2160 的有效 JPEG，分别加载 1.4.1 与修复代码。16 个同图直接读取从 16 次读盘/16 个缓冲区/109,351,472 字节，变为 1 次读盘/1 个缓冲区/6,834,467 字节；后续篡改磁盘仍会检出，不是跳过摘要的永久内存缓存。

慢连接使用真实回环 HTTP，客户端收到响应后暂停读取一秒。为减少分配器复用干扰，下表每个场景在独立进程运行，并按 5ms 间隔采样 Node 内存；RSS 是本机观测值，不是全平台或生产容量承诺。

| 场景（16 连接） | 修复前 | 修复后 |
| --- | --- | --- |
| 同图实际读盘次数 | 16 | 1 |
| 同图峰值 arrayBuffers | 114,808,175 B | 19,446,954 B |
| 同图峰值 RSS | 60,321,408 B | 46,067,264 B |
| 不同图实际读盘次数 | 16 | 7；其余 9 个等待 |
| 不同图峰值 arrayBuffers | 114,808,607 B | 49,692,686 B |
| 不同图峰值 RSS | 123,202,944 B | 46,952,128 B |

修复后不同图场景 HTTP 峰值预留 62,914,560 B，低于 64 MiB；持有 47,841,269 B，断开后执行数、排队数、消费者数、预留与条目数均为零。同图 16 个慢响应仅持有一个原图缓冲区。自动回归还覆盖排队超时返回 503/Retry-After/no-store、消费者上限、独立 I/O 并发限制、全部等待者取消后实际读盘结束前仍保留预算、慢响应超时、HEAD、失败/过大结果恢复及健康接口可用。

此预算针对应用缓冲区与生命周期，不能解释成整个 Node RSS、Sharp 或内核网络缓冲区上限。公网只执行正常浏览/下载和只读状态检查，不施加过载流量。
