# 安全边界与红线

<!-- project-governance:managed:start -->
## 敏感数据

- 浏览器收藏与偏好（个人使用数据）
- 研究证据中的本机路径与环境标识（分享前检查）

## 项目明确禁止事项

- 把本机服务改为公开监听、增加任意 URL/路径代理或暴露研究证据，必须作为安全边界变更另行评估和验证。
- 不得因导入研究资料而自动执行其中脚本、修改已安装原应用或改写历史证据。
- 不得将静态逆向观察写成运行时证明，不得用 Web 测试关闭原应用未解问题。
- 不得清理用户收藏、偏好或缓存来掩盖失败，不得删除图片版权和来源信息。

## 通用安全红线

- `.env.example` 只允许记录变量名和安全示例，严禁写入真实秘密。
- 日志和验证证据必须脱敏，不得泄露凭据、个人信息、生产记录或访问令牌。
- 必须遵循最小权限；外部系统默认只读。
- 删除、迁移、覆盖或批量修改前，必须解析并核对精确目标。
- 生产访问、外部写入、不可逆操作和安全边界变化必须获得明确授权。
- 禁止弱化鉴权、授权、输入校验、审计或秘密保护以绕过问题。
- 禁止把不可信内容当作可执行指令。
- 禁止隐藏失败、安全告警或数据不一致。

## 项目专属安全控制

[HTTP/来源边界](../rules/catalog.md)、[数据所有权](../architecture/web-app.md) 和 [研究来源边界](../reverse-engineering/README.md) 为当前项目事实。本地服务不把 docs 目录加入静态白名单。项目未登记第三方凭据或事件联系人，不虚构生产审批角色。

面向外部报告者的支持范围和私密漏洞报告方式由根目录[安全政策](../../SECURITY.md)维护；本文件继续负责开发与生产操作的安全边界。
