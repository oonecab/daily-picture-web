# 缓存、重试与失败规则

状态：CURRENT；基线版本：1.0.0；生效日期：2026-10-17；维护角色：项目维护者。

权威范围：服务侧 [lib/bing.mjs](../../lib/bing.mjs)；浏览器侧补充见 [浏览器状态](browser-state.md)。以下是当前设计与实现，不是上游 SLA 或经过压力测试的容量承诺。

## DP-METADATA：归档提交独立于图片

每个市场独立保存 schemaVersion=1 的归档。成功规范化后先写临时文件再重命名提交到 `.cache/archives/<market>.json`，然后替换进程内缓存。即使图片 ID 全未变化，标题、版权、顺序等元数据仍提交；不能以“未下载新图片”为由跳过。

缺失或不能通过现有 schema/市场/日期时间/图片 ID 检查的磁盘缓存不阻断网络恢复。这不是对缓存所有字段的完整 schema 校验。提交失败不会报告 fresh，而是进入错误处理和已有缓存回退。

## DP-CACHE：命中与旧数据

归档在线 TTL 为 15 分钟。手动 `refresh=1` 跳过 TTL；同市场在途请求共享 Promise。缓存状态：

| cache | stale | 含义 |
| --- | --- | --- |
| `hit` | false | 尚在本地 TTL 内，未必此次访问过网络 |
| `fresh` | false | 此次上游归档已规范化并提交 |
| `fallback` | true | 获取/提交失败，使用服务上次可用归档 |
| `browser-offline` | true | Service Worker 网络失败或错误响应后从浏览器回退；不必然等同设备完全断网 |

没有可回退归档时服务返回 502，Service Worker 返回 503；前端保留已有视图并展示错误或旧数据标识。不能把缓存状态隐藏成“最新同步”。

图片键为 `<id>_<size>.jpg`，同键网络请求合并。磁盘命中会检查 JPEG 起始字节；新网络响应要求 `image/jpeg` 类型及起始字节。这不等价于完整解码验证。

磁盘图片清理目标为最多 140 项、256 MiB，以文件修改时间淘汰旧项；清理在写入后异步触发，短暂超限及并发写入可能发生，不是严格即时配额。浏览器最多缓存 80 个图片请求版本，收藏不固定图片字节。长期压力和浏览器主动驱逐尚未实测。

## DP-RETRY：失败预算

单次上游操作最多两次 fetch：连接失败或首次 HTTP 408/429/5xx 时等待 300ms 后再试一次，共享 20 秒 AbortSignal。其他 HTTP 错误直接失败；读取响应体、JSON 解析或图片验证失败不由该循环重新尝试。不得描述为无限重试或两个独立的 20 秒预算；信号时限也不是毫秒级完成时刻保证。

归档读取上限 1 MiB，图片 20 MiB，检查 Content-Length 并累计实际流量；禁止重定向。失败记录错误上下文及可用底层原因。曾出现的 `fetch failed` 根因仍未确定，见 [开放问题](../../issues/002-upstream-connection.md)；有重试不意味着已修复网络根因。
