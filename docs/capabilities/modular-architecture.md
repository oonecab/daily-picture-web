# 模块边界规范

<!-- project-governance:managed:start -->
本能力由 capabilities 显式启用，不要求所有项目采用分层、单体或微服务中的某一种架构。

- 在 `TECH.md` 或其链接的唯一架构文档中记录当前模块职责、公开入口、依赖方向和数据所有者；目标设计与已实现事实分开，不把计划写成现状。
- 跨模块调用通过已声明的公开接口；例外需说明必要性、影响和撤销条件，不能把某一项目的包名或存储设计强加给其他项目。
- 重要边界关联项目自身的契约/架构测试或明确评审证据；修改边界时同步事实、调用方说明与回归测试。
- 生成器只维护本规范，不扫描任意语言的依赖图，也不证明代码已遵守边界。
