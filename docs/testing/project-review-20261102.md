## F1：代理占位图可以污染共用离线图片缓存（已复现，优先修复）

位置：public/sw.js:93–100（命中立即返回，仅 direct=1 开启尺寸验证）；lib/bing.mjs:235（近期代理 JPEG 类型与起始字节检查）；lib/image-cache.mjs:37（磁盘 JPEG 起始检查）。依据：同图直连/代理复用键、拒绝占位图遮蔽回退、失败后可恢复。

实验一：执行当前 SW 源码，先输入 direct 占位图再输入 proxy 占位图，前者不缓存、后者缓存；上游变为健康后，direct 仍返回 placeholder-image，网络调用数保持 2。

实验二：真实 Chrome 156.0.8078.79、隔离浏览器上下文、随机本地回环端口、当前 createApp 和真实 SW，使用 Sharp 生成有效 1×1 JPEG，由受控 service.image 返回。代理请求将其缓存；将后端切为 640×360 正常 JPEG，再请求同 ID 的 direct=1，实际解码仍为 1×1、HTTP 200、后端累计仅调用 1 次。不是仅验证“调用过某函数”。未向生产注入占位图，未声称生产已发生该故障。

影响：特定图片可持续显示失败/占位图，直到条目被淘汰或删除。跨 direct/proxy 共用键使恢复请求也被拦住。过往 direct-placeholder 回归只覆盖 direct 写入这一方向。

最小改进：对共用键的所有新写入采用一致校验，兼顾已有坏条目的命中恢复；近期服务端缓存也应避免持续返回已缓存占位图。不得通过清空所有收藏/缓存掩盖恢复问题。

验收：direct 坏→proxy 好；direct 坏→proxy 坏→上游好；预置旧坏缓存→恢复；有效小尺寸缩略图边界；无 createImageBitmap 环境明确降级。检查最终图片解码尺寸、真实网络恢复次数及收藏不变。

## F2：自动刷新调度器失效不会使浏览器逻辑测试失败（测试缺口已证明）

位置：test/browser-ui.test.mjs:120 的 setInterval 返回常量，clearInterval 无操作；默认设置 autoRefresh=false；尾部跨天测试仅用 2000/9999 日期直接调用 refreshDue。public/app.js:462 是实际调度入口。

隔离突变实验仅在私有测试副本加载源码时将 scheduleRefresh 整个函数替换为空函数，不改工作区源文件；34 项 browser-ui 测试全部通过。因此不能从这些用例推导“自动更新调度已验收”。本轮并未发现生产调度器已经失效。

最小改进：测试边界增加可推进的 Date/计时器，记录并执行 interval、支持 clearInterval；通过打开自动刷新、推进时间、改变可见性来观测 archive 请求和最终背景，不依赖修改 backgroundPending 等私有变量。无需全仓库依赖注入重构。

验收：北京时间午夜前后、美国夏令时边界、上游发布延迟、自动刷新关闭、页面隐藏/重新可见、busy 状态、地区切换以及 pagehide/pageshow。正常日 60 分钟、缺当天图 15 分钟、检查粒度 60 秒分别断言；再次置空调度器必须稳定失败。

## F3：可重复浏览器门禁与 CI 触发范围不完整（结构事实，非生产故障）

位置：.github/workflows/collect-wallpapers.yml:1–14；package.json scripts；真实布局/线上验证脚本位于 Git 忽略的 .private/。

仓库确实有 npm test 的 GitHub Actions 步骤，但属于每日采集工作流，仅定时、手动或 main 上特定采集/后端路径变更触发。没有 pull_request 触发，也不覆盖普通 public/app.js、styles.css、sw.js 和 test 变更。因此不能说“完全没有 CI”，也不能把这条采集工作流当作每个 UI PR 的测试门禁。远端分支保护/外部 CI 本轮未查，不能声称不存在。

最小改进：独立只读验证 workflow，覆盖 PR 和相关 main 修改；将关键浏览器验证迁入仓库可重复运行的位置，固定数据夹具并通过条件等待断言状态，固定浏览器/工具版本，线上 smoke 与离线回归分开。不要让普通测试触发生产采集写入。

验收：只修改 CSS/SW/测试的 PR 应触发；故意破坏菜单边缘、背景开关或图片恢复应失败；全新 checkout 可按文档执行而不依赖已有 .private/ 文件。
