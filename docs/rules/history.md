## DP-HISTORY：年月目录与记录来源

仅支持中国区 zh-CN，范围为 2018-09 至 Asia/Shanghai 当前月；目录表示可查询范围，不保证每一天有记录。日期必须是真实公历日期且不晚于中国当天。zxyongyo 首月最早收录 2018-09-11，npanuhin 中国区始于 2024-04-03；首月可不满月，不为缺档补图。归档日期原样保留；Bing 新记录依 DP-DATE 转换，不根据 OHR 市场后缀更改源日期。

日常浏览读取本站 HISTORY_DIR 的月文件和缩略图；预览与原图按需从固定 Bing 地址加载，迁移时保留的副本由本站提供。第三方适配只能由明确的 import 模式使用；导入工具一次性读取两来源，保留摄影版权、来源与原始 ID，保存索引与缩略图到本站，迁移前的全量原图先在本地备份。按日期合并，每日一条、每月最多 31 条，降序展示；同日优先级 Bing > npanuhin > zxyongyo。ID 相同才合并贡献来源、图片备份标记与此前检查结果；ID 不同使用优先记录并重新检查，不借另一张图片填补失败。

两个 Bing 批次同日合并时，双方有合法 fullStartDate 且时刻不同时取较新发布时间；否则比较逐条 observedAt（该批 fetchedAt，兼容缺省时使用本机采集时刻）。不把较晚收到请求视为较新版本。发布时间/采集时间相同时保留已存在的不同 ID，同 ID 可更新说明并保留已保存状态和已知发布时间。旧文件没有 observedAt 时，以已有发布时间作为观测时间下界，不能被采集时刻早于该发布时间的快照替换；两者都缺失时以首次有采集时刻的新记录建立基线。未来超过五分钟的采集时刻拒绝入库。后台保存合并后的当前 ID，不能继续下载被淘汰的快照 ID。

每项保留 ID、市场、日期、标题、说明、版权、来源链接、source/sources、snapshot、availability；没有 Bing ID 的备份使用 OHR.HistoryCN_YYYYMMDD，不把该标识送给 Bing。普通 API 不请求用户提供的 URL。导入刷新不会删除本地已有、源端暂时缺失的记录。同一 Bing 采集窗口若同日有多个图片 ID，月索引及 latest.json 均取适配器按发布时间降序排列后的第一项。单个历史来源月数据出现非法地址、日期或结构时拒绝该批；本地导入工具额外隔离同日尺寸链接指向不同 ID 的记录，保留其日期/ID/原因到 import-report.json，不猜测正确链接。其余有效记录继续导入。

## DP-HISTORY-STORE：采集、持久化与恢复

HISTORY_DIR 默认项目根 .history；每月 YYYY-MM.json，schemaVersion=1。月数据和同步状态使用临时文件加原子重命名，同进程写入串行，合并前重新读取。损坏文件报错并保留，不能当成空文件覆盖。一个目录仅允许一个服务进程写入，导入必须在隔离目录；导入锁防止重复导入进程，异常退出后须确认进程结束再清理锁。重跑复用已保存的索引和图片，并生成本轮报告。

GitHub Actions 每日计划 UTC 21:17（北京时间次日 05:17），并支持手动运行；从 Bing 的 idx=0/7、n=8 两批取得最多最近十五日，完整验证后按日期合并到自己的 codex/wallpaper-data 分支。两批失败之一不更新 latest.json，也不提交数据分支；已有历史月文件保留。GITHUB_TOKEN 仅 contents:write，固定官方 action 提交，串行普通推送。调度可能延迟；不能将一次成功视为永久每日运行保证。

服务启动后立即读取自有分支 latest.json，此后每轮结束一小时重试；仓库由 HISTORY_REPOSITORY 指定，默认 oonecab/daily-picture-web。HISTORY_COLLECTOR=off 关闭本机后台采集。只接受 schemaVersion=1、zh-CN、1～15 条唯一有效日期、合法 ID 和字符串；fetchedAt 必须有效且不超过当前时间五分钟。超过 48 小时仍可补保存，但状态明确报告过期。每轮两张并行保存真实缩略图，失败保留索引并记录到 sync.json，下轮重试。预览与原图不在日常后台持久化。游客只读本站月索引；大图直连 Bing 或由本站受限按需代理，不访问两个第三方历史项目。

月索引中 source=bing 且未达到 thumbnailStored:true 的记录构成持久待补账本，不因退出十五日窗口或进程重启丢弃。每轮处理当前最多十五日，再补最多十五条窗口外记录；按上次检查时刻由早到晚、日期由早到晚选择，防止持续失败的图片占满后续批次。旧归档来源不自动重新导入。源索引验证失败时本轮失败，已有待补记录保留。sync.pending 表示整库待补数量，saved/total 表示本轮所有尝试、retryTotal 表示额外补齐批次；存在待补、当轮失败或索引过期时保持 error，只有全部补齐且索引新鲜时更新 lastMediaSuccessAt 和 lastThumbnailSuccessAt；mediaPolicy=thumbnails 明确本轮保存对象。保存失败的状态和时间继续保留，永久缺失也会有界重试，不伪装为成功。

近期中国区归档的成功读取仍追加元数据到本地月份，失败用 historyWarning 提示；缩略图由后台同步保存。sync.json 分别保留 lastSuccessAt（索引落盘）、fetchedAt（Actions 采集时间）、lastMediaSuccessAt / lastThumbnailSuccessAt（整轮缩略图保存成功）、失败明细和错误，不混淆写入时间与采集新鲜度。停机后可补最新十五日，超出窗口的遗漏无法保证找回。

月文件、永久缩略图及受保护副本独立于 .cache 淘汰。迁移前完整图库按媒体清单逐文件验证 SHA-256 并备份到本机；迁移后继续备份索引、缩略图和受保护副本。旧 schemaVersion=1 月文件兼容读取，逐来源 providers 和 importedAt 为可选字段。分层迁移停止服务写入后更新现有图库；清理前保留完整本机备份，清理后回滚须同时恢复原图、媒体清单及兼容索引。

## DP-HISTORY-IMAGE：图片可用性与资源预算

初次导入可请求历史来源；日常运行只使用 Bing 和自有索引。后台仅获取小图并用 Sharp 生成宽度上限 640 的真实缩略图，不把大图缩成界面尺寸充当缩略图。后台与历史按需请求沿用共享上游 4 槽/32 等待位置；同图候选共用 20 秒预算，JSON 上限 1 MiB、图片 20 MiB，禁止上游重定向。普通 API 不接受 URL 或文件路径。

Bing 图片 URL 由合法 OHR 标识与 UHD / 1920x1080 变体构造；仅 https://www.bing.com/th 与 https://cn.bing.com/th。旧图保留经审查的变体，不能因 UHD 失效丢弃仍有效的同 ID 旧地址。预览请求最大目标宽 1920，小图目标宽 640。迁移检查优先 UHD，再尝试同 ID 的历史变体；GET 成功、JPEG 类型、最小 320×180 和完整解码均通过才认为当前可用。清理还要求返回的原图宽高不低于已保存副本；分辨率数字不代表原生细节。

media 目录按日期和 ID 摘要命名。缩略图长期保存，清单保留字节数、SHA-256 和尺寸。迁移时失效、无法确认、低于原副本尺寸的图片保留原图和预览，delivery.mode=local；通过检查且备份验证完成的图片标记 mode=bing，释放原图/预览。校验时间超过 48 小时、未来超过五分钟、日期/ID 或备份摘要不匹配时不允许清理。全批次预检后才更改索引和删除精确文件；停止服务写入并持有迁移锁。工具可恢复已完成的清理步骤，禁止按通配符删除图库。

浏览器通过 direct=1 请求获得固定 Bing URL 的 302，使用匿名 CORS 展示/下载；受保护图片返回本站 JPEG。失败时回退到同日期、ID、尺寸的本站代理。历史预览直连等待超过 12 秒即使用同图本站代理，切图、成功加载或离开页面释放定时器。下载总预算 30 秒，其中浏览器直连最多 10 秒，为回退预留时间。代理完整解码校验后返回，图片仅进入与每日精选共享的 256 MiB 临时缓存；同图请求合并。两项完整解码同时执行、最多 32 等待，输入最多 40 百万像素，最长 15 秒。服务器不接受任意目的主机，CSP 仅增加上述两个 Bing 来源。

availability.thumbnailStored 表示长期缩略图已保存，stored 表示仍有本站原图；width/height 表示最近校验的原图尺寸，不能用缩略图尺寸填充。status/checkedAt 记录缩略图采集结果；delivery.original/preview 保存迁移检查的变体、尺寸、摘要和结果，不能把过去检查当成永久可用。新图仅保存缩略图后不保证未来仍能取得 Bing 原图；有本地完整备份的历史图可按需恢复副本。失败不删除索引，缩略图采集使用 60 秒失败冷却和持久重试。

临时缓存见 [缓存规则](cache.md)：每日精选与历史共用最多 140 项 / 256 MiB，启动恢复和串行写入前预留都执行淘汰；Nginx 禁止额外图片缓存及临时落盘。永久缩略图、受保护副本和浏览器缓存不计入该磁盘缓存预算。

1.4.2 图库同 ID/日期/尺寸的在途读盘共享一次摘要检查和一个缓冲区，完成后不作为永久内存缓存；后续请求仍校验磁盘。按媒体清单大小分配固定缓冲区，文件大小不匹配或超过 20 MiB 时拒绝读取。图库读盘池和 HTTP 图片响应池各有 64 MiB 预算、最多 4 个执行任务、32 个等待任务和 64 个消费者；启动读取前按 20 MiB 预留，读取后按实际大小计费。两池均覆盖实例内所有图片键，HTTP 池同时覆盖每日精选与历史图片；它们不是整个进程 RSS 或 Sharp/上游的合并预算。

HTTP 的相同图片请求共享缓冲区，预算持有至最后一个响应完成或连接关闭。排队最多 5 秒，容量不足或排队超时返回 503 + Retry-After:5；排队中断不启动读取。已启动但无人等待的读取仍占用预留，直到实际结束。发送阶段最多 30 秒，超时断开响应并回收预算；客户端下载失败可重新请求。健康和元数据接口不占图片预算，超载时仍可返回。慢客户端容量需独立于正常吞吐验证。

## DP-HISTORY-UI：按需浏览与声明

只读取所选月元数据，最多 31 项；切月取消旧请求并核对 generation，迟到结果不覆盖新月。缩略图接近视野 80 像素后入队，最多两张同时加载，切换列表/离开页面释放请求和槽位；缺少 IntersectionObserver 回退原生 lazy。只加载当前 Bing 预览或受保护预览，点击下载才取原图，不预热整月。各尺寸有不同 URL 缓存键，浏览器仍共用 80 项/64 MiB 图片预算；历史元数据缓存最多 13 项。永久缩略图与受保护副本不参与这些淘汰。

网站“关于每日一景”和图片详情保留历史来源，README 提供第三方声明入口，详细贡献集中于 THIRD_PARTY_NOTICES.md；摄影版权继续展示。首页页脚提供同步状态、Bing、项目源码和“关于”入口。空档、加载、失败分别提示，大图重试可按需访问 Bing，月索引重试只重读本站文件。离线可用范围取决于浏览器已保存且未淘汰的资源。
